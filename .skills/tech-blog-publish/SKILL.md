# 文章發布流程

以使用者確認過的中文文章為基礎，預設產生對應英文版，讓中英文文章、封面與分享資訊一起完成發布準備，並依本次授權完成提交與部署。沿用對話中已確定的內容與偏好，不因進入發布流程重新改寫中文定稿。

## 1. 確認文章與本次範圍

- 從對話找出目標文章，讀取目前檔案、frontmatter、專案 `AGENTS.md` 與 `git status --short`，辨認本篇相關檔案及其他未提交的工作。
- 使用者要求「準備發布」或「檢查能不能發布」時，完成本機準備與檢查；「幫我發布這篇」則依已確認的部署方式，完成必要的提交與部署。建立這份 skill 本身不代表要發布文章。
- 沿用使用者已給的發布、提交、推送與部署授權，不重複要求確認。若文章或部署目標確實無法判斷，先完成不受影響的準備，再只詢問缺少的資訊。

## 2. 定稿與引用

- 以使用者最後確認的版本為準。需要潤稿時讀取 [tech-blog-polish](../tech-blog-polish/SKILL.md)，但發布檢查不自動啟動大幅改寫。
- 保留作者的日常口吻、實際經驗與尚未確定的判斷。刪除重複解釋，不新增作者沒說過的工作經歷、使用數字或成效。
- 原話使用引號或引言框並附來源；摘要轉述以作者、節目或講者名稱搭配句內連結標明。已知講者時直接指名，例如「大人學的 Joe 建議」。作者自己的結尾重點若使用引言框，也要讓讀者看得出是作者的想法。
- 同一節目的介紹、音訊與逐字稿合併為同一筆參考資料。未核對音訊的轉錄限制可留在 Markdown 編輯備註，不把轉錄當成官方原話。
- 參考資料以實際引用與使用者指定為準，不因提到技術名詞就擴充閱讀清單。直接引用原文時列出原文；依二手文章整理時標示該文章。不要把編輯補查的來源寫成作者親自讀過的經驗。
- 確認正文來源連結對應參考資料；重新查核新增或有疑義的資料，不為了重新跑流程而重查已確認且未變更的來源。系列文章檢查相鄰篇章連結。

## 3. 產生對應英文版

- 準備發布或正式發布中文文章時，預設建立或更新英文版，不再每次詢問是否需要翻譯。使用者指定只發中文或本次只做唯讀檢查時，依指定範圍執行。
- 讀取中文最終版本後再翻譯。英文檔放在 `src/content/posts-en/`，與中文檔使用相同的相對檔名與文章 id，讓網站能辨識雙語對應。例如中文為 `src/content/posts/example.md`，英文就使用 `src/content/posts-en/example.md`。
- 翻譯完整正文、標題、小標、摘要、圖片說明、連結文字與參考資料說明。保留第一人稱、直接分享工作經驗的語氣，使用自然英文，不逐字硬翻，也不新增中文原稿沒有的經驗、數字、觀點或確定性。
- 保留引用的實際來源與連結，不為英文版另換成作者沒引用過的資料。來源原有名稱可保留，搭配英文說明；中文原話譯成英文時標明為翻譯。數字、人物、技術名詞與推測語氣需和中文一致。
- 英文 frontmatter 的 `title`、`description` 與有使用時的 `meta_title` 使用英文；分類與標籤參照既有英文文章的用詞，將中文詞彙自然翻譯，專有名詞保持一致。`authors`、`audience`、`date`、`updated` 與中文對齊，`image` 依實際選用圖片設定。
- 準備時讓中英文維持相同的草稿狀態，正式發布時一併公開。已有英文版時先對照內容，只同步本篇變更，保留獨立修訂；中文定稿後再有修改，也要同步檢查英文，不留下舊版翻譯。
- 系列連結指向對應語言的相鄰篇章；站內連結優先使用已存在的英文頁，沒有英文頁時保留可用來源，不猜測或生成不存在的 `/en/` 路由。

## 4. 封面與分享圖片

- 預設準備封面，因為文章會分享到 LinkedIn 等平台；使用者指定不放圖時略過。網站允許無封面，分享圖會改用站台預設圖片，不把封面當成技術上的發布門檻。
- 已有使用者確認的封面就沿用；需要新圖時使用可用的 `imagegen` skill，先查看現有文章封面，讓主題、比例與風格適合本篇。
- 中文版封面的文字使用繁體中文，英文版使用英文；無字或適合雙語讀者的封面可以共用。若現有圖片的中文標題影響英文版閱讀，再做相同構圖的英文版或無字版，不重做已合適的共用圖片。
- 圖中文字保持精簡，留出裁切空間。以縮圖也能辨識主題為目標，不把整篇文章塞進圖片。
- 最終圖片放在 `public/images/post/`，文章 `image` 使用 `/images/post/...` 路徑。生成器的預設輸出位置不能作為網站資產路徑。
- 實際看圖，確認文字、構圖與主題；確認檔案存在、可讀取及大小合理。已合適的封面不重新生成。

## 5. 文章設定

- 中文文章位於 `src/content/posts/`，英文文章位於 `src/content/posts-en/`。保留已確認的檔名與網址，不在發布前隨意更換 slug。
- 檢查 `title`、`description`、`date`、`authors`、`categories`、`tags`、`audience`，以及有封面時的 `image`。分類與標籤沿用使用者選擇，不把某篇文章的設定當成所有文章的預設值。
- 新文的 `date` 對應實際發布日期，依使用者時區處理；已發布文章保留原始日期，有實質更新時再處理 `updated`。未來日期不能取代排程功能，不把填好日期當成已排程。
- 本專案的 `draft: true` 會排除文章路由、列表等輸出。正式發布時將本篇中英文文章一併設成 `draft: false`；準備或檢查時保留原本的草稿狀態。
- 草稿若需要檢查實際頁面，可在本機暫時將本篇中英文文章設成 `draft: false`，檢查完分別還原。正式部署前必須依最終草稿狀態重新建置，避免部署包含暫時公開草稿的舊產物。

## 6. 本機預覽與檢查

針對本次內容執行格式檢查，不順手格式化整個專案。發布準備預設依序執行：

```powershell
npm run check
npm run build
npm run check:seo
```

- `check:seo` 讀取 `dist/`，必須在成功建置後執行。相同版本已有可用的檢查結果時可沿用，後續有修改才重跑受影響的檢查。
- 使用既有本機伺服器，或執行 `npm run preview` 預覽建置結果。中文路由為 `/posts/<文章 id>`，英文路由為 `/en/posts/<文章 id>`；公開網址的網域從 `src/config/config.json` 取得。
- 確認本篇中英文頁都確實產出，不能只因整站建置成功就判定文章已可發布。分別檢查正文、引用、封面、列表、分類與標籤連結，以及手機寬度的可讀性；使用者指定只發單一語言時只檢查該語言。
- 檢查兩個頁面的標題、摘要、canonical、`og:image` 與 `twitter:image`；確認分享圖片的路徑指向各自選用圖片，且本機能讀取對應資產。
- 檢查語言切換連到同一篇文章的另一語言、`html lang` 分別為 `zh-Hant` 與 `en`、`hreflang` 完整且雙向對應現有中英文頁。英文頁不能殘留中文標題或摘要；圖片文字依共用或分語言封面的選擇檢查。
- 檢查失敗時先修正本篇造成的問題。既有且無關的錯誤要清楚回報，不擴大成整站重構，也不在檢查未通過時宣稱已準備完成。

## 7. 提交與部署

- 需要審閱變更或建立提交時，讀取 [git-change-commit-review](../git-change-commit-review/SKILL.md)。將本篇中英文文章與封面納入同一次發布，只提交這次發布相關檔案與必要修改，保留其他未提交的工作。
- 依專案規範提供繁體中文 commit 主旨與 body，不加 `Co-Authored-By`。
- 先確認實際部署平台與觸發方式。本專案同時保留 Cloudflare、Vercel、Netlify 設定，不能僅憑某個設定檔存在就選它部署，也不要將所有部署入口都執行一次。
- 已確認使用 Cloudflare Workers 時，可使用 `npm run deploy:cf-workers`；若使用 Git 推送觸發託管平台建置，依已確認的分支與既有流程執行。目標不清楚時，將文章、封面、預覽與檢查結果準備好，再詢問部署目標。
- 部署完成後開啟本篇中英文正式網址，確認正文與圖片可讀取、語言切換及分享資訊正確，再回報「已發布」。只完成本機修改、commit、push 或啟動遠端建置，都不等於已確認上線。

## 8. LinkedIn 分享準備與交付

- 完整發布流程預設準備一則可複製的 LinkedIn 分享文案；使用者只要檢查文章，或指定不需要文案時略過。撰寫前讀取 [linkedin-blog-promo](../linkedin-blog-promo/SKILL.md)，使用本篇最終內容與正式網址，不編造工作場景。
- 文案依使用者選擇的語言附上對應文章連結；未指定時沿用繁體中文。產生英文文章不代表要另發一則英文 LinkedIn 貼文。
- 尚未上線時，文案明確標示連結待確認；上線後才提供已驗證的正式連結。分享預覽檢查封面、標題與摘要；無法取得平台實際預覽時，區分本機 metadata 已檢查與平台預覽尚未確認。
- 準備文案不等於替使用者發文。只有使用者明確要求在指定平台發布時，才使用相應工具執行。
- 結束時簡短列出中英文文章狀態、兩份文章與封面位置、檢查結果、雙語正式網址或尚缺的部署資訊，以及分享文案。清楚區分「草稿已準備」、「檢查通過」與「已確認上線」。
